# 独立桌面浏览器 App 产品形态

## 1. 最终交付边界

最终产品是独立安装和运行的 Chromium 系桌面浏览器，不是控制个人 Chrome 的脚本，也不是要求用户单独维护的 Node/Python 服务。首个开源版已选定 Electron；`stock Chrome + sidecar` 保留为执行引擎对照适配器，后续可增加 Chromium/BrowserOS 底座。

### 原生浏览器层

- 窗口、标签页、地址栏、前进/后退、刷新、收藏、历史、下载。
- Profile 选择、账号/任务隔离、权限管理、设置、数据清除。
- 原生挑战接管、agent 会话面板、动作时间线、快照证据、模型与设置管理。
- Windows 安装/卸载、代码签名、自动更新、回滚、崩溃恢复。

### 内嵌 agent 运行时

- MCP、BrowserRuntime、ChallengeBroker、CapabilityRegistry、AuditLog 随 App 生命周期运行。
- 默认仅绑定本机或命名管道，不开放公网控制端口。
- AI 与人工共用页面，但控制权租约明确；人工接管时自动读写硬暂停。
- 鼠标、键盘、剪贴板默认按 Profile/会话虚拟化，系统全局模式需显式开启。

## 2. Profile 与身份

每个 Profile 包含独立 Cookie、LocalStorage、IndexedDB、Cache、Service Worker、权限、密码本、虚拟剪贴板和审计命名空间。Profile 用于区分账号或任务，不以“新开标签页”冒充隔离。

密码填充由原生凭据能力完成：

1. 校验当前 origin、Profile 和凭据绑定关系。
2. 不向模型返回密码、OTP、Cookie、私钥或完整输入值。
3. 审计仅记录 Profile 标识、origin、凭据能力版本、填充结果和时间。
4. 新 origin、疑似钓鱼域、跨账号变化和高风险操作需要人工确认。
5. 密码本导出、复制和远程同步属于独立高权限能力，默认关闭。

## 3. 既有数据导入矩阵

| 数据 | 目标方式 | 承诺边界 |
|---|---|---|
| 书签 | 浏览器原生导入或标准 HTML | 可支持，导入前预览 |
| 历史 | 用户显式选择来源与时间范围 | 默认不导入，不进入模型 |
| 密码 | 原生向导读取用户主动提供的官方导出文件，写入受保密库 | 不经 MCP、不写日志；源文件由用户处置，不承诺 SSD 安全擦除 |
| Cookie | 同 Windows 用户、兼容 Chromium 版本的原生迁移，或重新登录 | 不承诺跨版本/跨机/跨应用无损复用 |
| LocalStorage/IndexedDB | 仅完整兼容 Profile 迁移 | 不提供任意站点通用复制承诺 |
| Service Worker/Cache | 优先重新建立 | 复制可能产生版本和来源不一致 |
| 客户端证书/私钥 | 操作系统证书存储与用户授权 | 不复制到普通 Profile，不进入 agent 能力 |
| BrowserOS neo 登录态 | 优先在原平台导出/重新登录，兼容时原生迁移 | 不直接接管现有 neo Profile 目录 |

任何导入失败都必须显式报告部分成功数量、失败项和原因，不得将“文件复制完成”报告为“登录态继承成功”。

## 4. 底座候选

### Chromium/BrowserOS fork

优点：完整浏览器 UI、Profile、扩展、密码管理和 Chromium 行为最接近最终产品。代价：构建链、签名、安全补丁、上游同步和发布工程成本最高。

### Electron shell

优点：桌面壳和打包迭代快，可复用现有 Node 运行时。代价：Chrome 扩展、密码管理、Profile 迁移与完整浏览器行为需要额外实现；先做 Electron 再迁 Chromium 可能形成双套 UI 和双套数据格式。

### 决策闸门

1. 完整 Chrome 扩展与原生密码管理是否为首发刚需。
2. BrowserOS 上游许可证、源码可构建性、Windows 签名和升级链是否可复用。
3. Electron 能否用一个不超过两周的 spike 验证 Profile、密码本、WebContents/CDP 和安装包，而非只验证窗口。
4. 是否存在必须修改内核的虚拟剪贴板、原生凭据填充、审计或人工接管需求。
5. 上游安全补丁同步的人力和构建成本是否有持续预算。

在闸门完成前，不启动双套 App UI。当前执行引擎、MCP、能力注册表和审计模型保持底座无关。

## 5. 其他必须纳入的产品能力

- 多 Profile/多账号并发与标签归属。
- 原生下载管理、恶意文件检测、上传外发确认。
- 扩展白名单、企业策略、签名与供应链。
- 崩溃恢复、动作幂等、任务恢复和重复副作用防护。
- 模型资源预算、离线模式、远程模型出网策略。
- 审计防篡改、数据保留期、敏感数据扫描与删除。
- 无人值守模式 fail-closed、人工接管通知和超时策略。
- 可访问性、键盘操作、多语言和高 DPI。
- 自动更新失败回滚、上游安全补丁 SLA、卸载数据处置。
